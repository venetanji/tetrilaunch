# Tetrilaunch 1.0.8

Status: release preparation. The selected source changes and this version record
are separate PRs targeting staging. Nothing in this record means they have
already merged or that a tag has been published. The PR bodies record exact
validated heads, test results and review status.

## Scope

| Change | Source |
| --- | --- |
| Keep RevenueCat's separate Android paywall activity in the game's landscape orientation. | PR #248, `claude/android-paywall-landscape` |
| Add Pixel Dreams as the first menu theme, retain the earlier menu songs, and preserve the current bay music through ordinary pause/resume. | `claude/pixel-dreams-pause-continuity` |
| Set app/desktop manifests and both lockfile roots to 1.0.8; update store notes and this record. | `claude/release-1.0.8` |

The orientation PR changes the regeneration patch for the ignored Android
project. It declares the exact RevenueCat `PaywallActivity` with
`android:screenOrientation="behind"`; ordinary manifest merging retains the
SDK's other attributes. The current dashboard paywall is reused.

Pixel Dreams becomes `menu.mp3`; the previous menu track remains available as
`menu-lounge.mp3`, alongside `menu-alt.mp3`. The first audible menu start plays
the main theme, and subsequent returns may choose any of the three. Ordinary
pause keeps the existing bay music element and playback position. Mid-bay
stingers still pause with the game clock; end-of-bay stingers still stop music.

There is no save or economy change, database migration or leaderboard clear.
Electron paywall behavior is unchanged. The original music masters remain local;
only processed audio assets are shipped.

28 manifest regression assertions, all 3,795 Chromium UI-fit combinations with
zero new/stale/grown baseline entries, and web/native builds. Gradle's merged
manifest has exactly one matching activity with `screenOrientation="behind"`

controls were reachable. Terms and Privacy opened their actual pages. Opening
and backing out in normal physical landscape preserved the viewport, game screen,
save, settings and WebView instance. Restore found an existing real Play Store
Full Game entitlement; no purchase was made. The owner accepted the orientation
result and asked to move on to music.

## Delivery

1. Review the selected orientation and audio PRs and obtain the owner's approval
   of the concrete merge-and-tag scope before any merge or main/tag push.
   Merge the selected source PRs into staging in
   order after resolving confirmed review findings. Update this record's branch
   against that staging tree, validate the combined result and merge it last.
2. Run from `app/`: `npm run typecheck && npm test && npm run test:uifit && npm run build`.
   Confirm zero new/stale/grown UI-fit entries; do not rewrite baselines to pass.
   Check final-head CI, native/store-bundle verification and store-copy limits.
3. Run `RELEASE_TAG=v1.0.8 node app/desktop/scripts/check-version.mjs` from the
   repository root. Separately compare both `version` and `packages[""].version`
   in both app/desktop lockfiles with the two manifests.
4. Fast-forward main to the exact verified final staging commit and push main.
   Create and push `v1.0.8` once on that main SHA under the approval from step 1.
   Do not replace the fast-forward with a PR merge into main.
5. Monitor the independent Android, iOS and desktop Actions runs. The tag sends
   Android to Play internal testing, iOS to TestFlight and desktop installers to
   the public GitHub Release. The owner handles environment approvals and
   subsequent public store promotion/submission.

Current live protection rules checked on 2026-10-16 require the owner's review
for `android-build`; `ios-build` and `desktop-build` have branch/tag restrictions
without required reviewers. Recheck at delivery. For a failed tagged job, prefer
rerunning that original job; do not delete/re-push the tag or burn another mobile
build number through a duplicate upload.

Production Worker deployment and Steam upload remain separate owner decisions.
Neither is a prerequisite for the tag's native testing builds.
