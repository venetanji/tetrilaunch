# Tetrilaunch 1.0.6 — release plan

Tracking document for the 1.0.6 release. The PR that carries this file is the
release's task list; the sections below are filled in by the review and
planning passes and checked off as the work lands.

## Scope

- The double-gameplay UX: front door + tier hub redesign (PR #223).
- Everything merged to `staging` since `v1.0.5` (24 commits at the time of
  writing): Workshop plates, Steam Deck controller parity, /about landing page,
  Steam packaging and store plan.
- Three new music tracks (masters generated locally, mapped in
  `app/scripts/prepare-audio.mjs`).
- Store screenshots regenerated from the shipped build for every listing size
  (`sim/promo/run.ts --shots`), plus the promo montage beats.

## Release notes (draft)

Paste-ready for the release body and the store "what's new" fields.

### Play

- Flight School is an offer now, not a gate. Press Play and you can take the
  lessons or go straight to Tier 1; either way you fly licensed.
- Quitting a bay drops you back at the tier hub — the Workshop, the Contracts
  board and the tower are one button away instead of a screen away.
- A finished tier waits for you. Land the run, clear the Contracts, then press
  **Unlock** when you want the ride: the next Mark opens on your say-so.

### Hub

- The menu is two screens: a front door that just starts the game, and a tier
  hub that holds the run, the Contracts and the Workshop as three cards, each
  with its own button.
- The tower fits all eleven floors without scrolling, and the Flight School
  lobby is gone from it — the ladder is the ladder.
- A square **!** marks whatever is new since you last looked. Press the thing
  it is sitting on and it goes out, and stays out.
- Today's Contracts sit on the hub as three chips you can start from where you
  are standing.

### Workshop

- The shop no longer scrolls. Every system is a plate in one panel, grouped by
  where it is — in the rack, in the shed, on the shelf — so you can read your
  whole rig at a glance.
- Pick a plate and the detail panel says what the next tier actually does, in
  numbers, instead of a price and a name.
- A padlock means you cannot have it. A system you are already flying is never
  locked and never dimmed, even when its next rung is over your Mark's budget —
  the budget says so itself.
- Tier 3 says out loud that it is a refit-stop part, bought with scrap on a
  run, not with salvage here.

### Desktop & Steam

- On a controller, **A** clears the tier-unlock banner instead of launching a
  run behind it.
- The pad scrolls a panel before it leaves it, so the Owned/Installed strips
  and any gated card below the last button are reachable without touching the
  screen.
- The bay banner and the "letting the bay settle" note scale with the field, so
  a docked Deck or a high-DPI monitor no longer shows two low-res islands in a
  crisp HUD.
- Riding the elevator to Flight School rolls the licence mark onto the plate,
  not "-2".
- Fullscreen is a Settings toggle on desktop rather than a third button on the
  field (F11 and ⌃⌘F still work, and the toggle follows them). *(rides only if
  #221 lands — see the merge train.)*

### Fixes

- The top tier is claimable again: finishing the last Mark's two halves now
  opens the seal phase instead of quietly doing nothing.
- The Workshop panel no longer scrolls sideways by 4px, and the top row's
  badges are not clipped by the panel edge.
- The promo page and its gallery are not shipped inside the game any more —
  about 3.7 MB of marketing left every Android, iOS, desktop and Steam build.
- The desktop build cannot open a web checkout for in-game content; the store
  door is closed in the shell by construction, not by an unset key.

## Risk list

**Save format — the only field that is genuinely new is `acked`.** `meta.ts`
and `lib/store.ts` are **unchanged between `v1.0.5` and `staging`** (verified:
`git diff v1.0.5..origin/staging -- app/src/game/meta.ts app/src/lib/store.ts`
is empty), so every save risk in 1.0.6 arrives with #223.

- `acked?: Partial<Record<NextStepId, string>>` — optional, defaults `{}` in
  `newMeta()`. `loadMeta` reads it off `raw`, drops anything that is not a
  plain object of strings, and needs **no migration**: absent reads as "nothing
  acknowledged", which is true of every pre-1.0.6 save. It fails *lit* (one
  extra glance at a button), never dark. **Low risk.** Confirm the follow-up
  commits keep that defensive read, and that `NextStepId` values are only ever
  written as keys (a renamed step id orphans an entry; harmless, but it re-lights
  the badge once).
- `NextStepId` gains `"unlock"`. A save written by 1.0.6 and loaded by a 1.0.5
  build carries `acked.unlock` as an unused key — `loadMeta`'s spread keeps it,
  nothing reads it. **Forward-compatible.**
- **Deferred claim is a real behaviour change to banked state, with no schema
  change.** `tierRunDone` / `tierContracts` now sit true-and-unclaimed until the
  player presses Unlock. A save caught mid-tier by the update is *correct* — it
  simply arrives on the hub with the Unlock button lit. **Verify** that a save
  which finished both halves under 1.0.5 (and so already advanced) does not
  light Unlock again: `tierReady` requires `tierRunDone && tierContracts >=
  TIER_CONTRACTS_REQUIRED`, and `advanceTier` resets both — so a 1.0.5 save is
  already reset. Worth one explicit test with a real save.
- `completeOnboarding` writes `licence = SCHOOL_FLIGHTS` in one go. Idempotent
  and monotone; a player who climbed the ladder is already there. The
  `celebratedMark` / `licence` grandfathering in `loadMeta` is untouched.

**Scores and economy.** No D1 migration is pending: `migrations/` still holds
`0001`–`0003` and nothing was added since `v1.0.5`. README calls `DELETE FROM
scores` the one irreversible step in a release — **1.0.6 does not need it.**
Tiers, `budgetForMark` and the board key are unchanged, so 1.0.5 scores stay
comparable. The only economy-adjacent change is *when* the Mark advances, not
what anything pays: the salvage shares are still banked by the recorders, and
`claimTierUnlock` pays only the award's rounding remainder. **Do not clear the
board.** If the merge train's re-validation shows a payout difference, stop —
that would make it a score migration and change the release's shape.

**Routing.** The largest behavioural surface. Home splits into front door and
tier hub; the Flight School lobby is removed from the tower; quit-from-run and
the coach-fail card's Menu now land on the **hub**, while Settings / How to Play
/ the hub's own back still go to the **front door**. Risks: a back-stack that
strands a player on the front door mid-tier, pad focus (`focusInitial` parks on
`.btn--primary`) landing on the wrong card, and deep links / resume paths that
assumed one menu screen. `sim/uifit` fixtures and the chromium baseline were
already updated on the branch (874 lines of `baseline.json`), which is the
signal to read closely rather than rubber-stamp.

**Native build inputs.** Unchanged by this release, and that is the claim to
check rather than assume: `ios.yml` passes `MARKETING_VERSION` from
`app/package.json`; `android.yml` takes `versionName` from the tag and
`versionCode` from `github.run_number`; `desktop.yml` runs `check:version` with
`RELEASE_TAG` before anything expensive. The `closeBundle` plugin that strips
`about/**` runs on the `NATIVE_MODES` set only — a change to the mode list would
silently put 3.7 MB back into every package, so `verify:store` and a package
size glance both belong in the QA pass. `verify:store:desktop` must stay green
for the Steam depot tree.

- [x] `app/package.json` → `1.0.6`
- [x] `app/desktop/package.json` → `1.0.6`
- [x] `app/package-lock.json` — **root entries only**, by hand: the top-level
      `version` and `packages[""].version`. No `npm install`.
- [x] `app/desktop/package-lock.json` — same two entries.
- [x] `node desktop/scripts/check-version.mjs` → *version 1.0.6 (app and desktop agree)*
- [x] `RELEASE_TAG=v1.0.6 node desktop/scripts/check-version.mjs` → *matches tag v1.0.6*
- [x] `npm run typecheck` clean
- [ ] Nothing to edit for **iOS**: `ios.yml` passes `MARKETING_VERSION` from
      `app/package.json`, build number from the run number.
- [ ] Nothing to edit for **Android**: `versionName` from the tag
      (`v1.0.6` → `1.0.6`), `versionCode` from `github.run_number`.
- [ ] Nothing to edit for **desktop**: electron-builder reads
      `desktop/package.json`'s version into the NSIS uninstall entry,
      `CFBundleShortVersionString` and the AppImage desktop entry — which is
      precisely why `check:version` refuses a tag that disagrees.

## Release steps

1. Merge the train above into `staging`. `staging.yml` deploys the staging
   Worker (its own D1, `tetrilaunch-leaderboard-preview`) on every push.
2. QA on staging (next section). Do not tag anything that has not been played.
3. Fast-forward `main`:
   ```bash
   git checkout main && git merge --ff-only staging
   ```
   Nothing deploys on this push — `staging.yml` is branch-filtered to `staging`
   and `android.yml` deliberately excludes `main`.
4. Tag and push:
   ```bash
   git tag v1.0.6 && git push origin v1.0.6
   ```
   The tag then drives, in parallel:
   - **`desktop.yml`** — `check:version` with `RELEASE_TAG=v1.0.6` first, then
     Windows / macOS / Linux packaging in the `desktop-build` environment and a
     GitHub Release with the artifacts. It does **not** upload to Steam: that is
     a separate `workflow_dispatch` with `steam_upload` ticked, and it goes to
     the `playtest` beta branch only. Promotion to the default branch stays a
     manual click in App Admin.
   - **`android.yml`** — the signed `.aab`, published to the Play **internal**
     track. Promotion past internal stays human.
   - **`ios.yml`** — archives with the manual App Store profile and uploads to
     **TestFlight**. App Store submission stays a click in App Store Connect.
5. Production Worker is manual and stays manual: run `production.yml` by
   dispatch (protected environment, required reviewer). It serves
   `tetrilaunch.com` off the same build.
6. **No `db:migrate` and no board clear this release.** `migrations/` is
   unchanged since `v1.0.5`; `DELETE FROM scores` is the irreversible step and
   1.0.6 does not earn it.

## QA pass (local session)

**On the USB phone** — the OnePlus CPH2573 over USB, via the repo's `test-prs`
command (`.claude/commands/test-prs.md`): it merges the open PRs onto a
disposable branch, builds a debug APK and installs it. Screens to eyeball, in
the order a player meets them:

1. Front door → Play → the tutorial offer. Take it once, skip it once; confirm
   both land in the hub with Tier 1 open.
2. Tier hub: the three cards and their buttons, the Contract chips, the tower
   rail, the leaderboard icon.
3. The alert mino: it appears on something new, and goes out when that thing is
   pressed — and stays out after a hub re-render.
4. Unlock: finish a tier's two halves, confirm the button lights, press it, and
   watch the ceremony ring. Then confirm it does not light again.
5. Quit mid-run from the pause card → lands on the hub, not the front door.
6. Workshop: the plate panel at 915×412 with no vertical *or* horizontal
   scroll, a locked plate, an owned plate at budget (must not be dimmed), and a
   detail panel showing tier stats.
7. Contracts board, and the tower with all eleven floors visible.
8. Top tier: claim it and confirm the seal phase opens.

**Fleet** — `npm run test:uifit` over the 24-device fleet (`sim/uifit/devices.ts`:
Android 640×360 budget through Pixel Tablet, iPhone SE 3 through iPad Pro 12.9,
web 800×600 through 2560×1080 ultrawide). `new` must be **0**; a moved baseline
is a decision, not a diff to accept. `npm run test:uifit:shots` for the screens
that changed shape.

**Bundles** — `npm run verify:store` (RevenueCat SDK survived, no Test Store
key) and `npm run verify:store:desktop` (no purchase surface in the depot tree).
`npm test` for the systems smoke test. Check `dist/` has no `about/` after
`npm run build:native`.
