## iPhone testing before release

The checked-in Xcode project and Capacitor package target iOS 15.0. Confirm the old iPhone model and installed iOS version, then validate the actual signed build's compatibility; a source deployment target alone is not device evidence.

Use [the iOS runbook](../ios.md) and `ios.yml` as the current references; `docs/NATIVE.md` still contains obsolete statements that iOS CI/signing are unavailable.

Current `ios.yml` behavior:

- A branch `workflow_dispatch` is a signing/export rehearsal. It produces a signed IPA artifact and does **not** upload to TestFlight, even if `publish` is selected on a non-tag ref. It is not automatically an installable ad-hoc build.
- Upload requires a `v*` tag: a tag push uploads automatically; dispatch on that tag also requires `publish=true`. A tag also starts Android and desktop release pipelines, so do not create a throwaway release tag merely to test an iPhone.
- A pre-release TestFlight path independent of release tags needs a separately reviewed workflow change and upload approval. Alternatively, use an approved local Xcode device build with the owner's signing/device setup. Neither path is part of this metadata PR.
- `ios-build` requires distribution certificate/password, App Store Connect API key/id/issuer, Apple team id and the RevenueCat iOS SDK key. Google iOS client id is warn-only. Confirm environment approval rules, signing validity, App Store profile/bundle identity, tester access and monotonically increasing build number with the owner. No secret values are needed in this PR.
- On the actual old iPhone: launch/update without losing saves, rotate/background/resume, restart, repeated input, audio interruption, crowded-pile pacing, login, purchase/restore and test leaderboard routing. Record build/commit and device/OS.
