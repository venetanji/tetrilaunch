# iOS (Capacitor) — build, sign, ship

The native iOS project lives in **`app/ios/`** and is committed to the repo. Everything
below assumes a paid **Apple Developer Program** membership ($99/yr — required for
TestFlight and the App Store; a free Apple ID can only side-load to your own device for
7 days).

| | |
|---|---|
| Bundle ID | `com.tetrilaunch.app` (`PRODUCT_BUNDLE_IDENTIFIER`, set from `capacitor.config.ts`) |
| Display name | Tetrilaunch |
| Devices | iPhone + iPad (`TARGETED_DEVICE_FAMILY = 1,2`), **landscape only** |
| Min iOS | 15.0 |
| Signing | Automatic (`CODE_SIGN_STYLE = Automatic`) — pick your team in Xcode |
| Capacitor | 8.x — dependencies via **Swift Package Manager**, no CocoaPods |
| Plugins | `@capacitor/haptics`, `@capacitor/screen-orientation`, `@revenuecat/purchases-capacitor`, `@revenuecat/purchases-capacitor-ui` |

## 1. One-time setup on the Mac

Requires macOS with **Xcode 16+** and Node 20+. No `pod install` — Capacitor 8 resolves
native dependencies through SPM (`ios/App/CapApp-SPM/Package.swift`, regenerated by
`cap sync`), and Xcode fetches them on first open.

```bash
git clone https://github.com/venetanji/tetrilaunch.git
cd tetrilaunch/app
npm install
cp .env.example .env          # add your RevenueCat public SDK keys
npm run ios:sync              # build → verify store bundle → copy into ios/
npm run ios:open              # opens ios/App/App.xcodeproj
```

`ios:sync` is the command to re-run after **any** web change. It copies `app/dist/` into
`ios/App/App/public/`, which is gitignored because it's a build artifact.

> The SPM packages are referenced by relative path into `node_modules/`, so `npm install`
> has to have run before Xcode can resolve them.

## 2. Point the project at your developer account

1. **Xcode → Settings → Accounts → +** → Apple ID → sign in with the account holding the
   membership.
2. Project navigator → **App** target → **Signing & Capabilities**:
   - **Automatically manage signing** ✓, **Team** → your team.
   - Bundle Identifier stays `com.tetrilaunch.app`.
   - **+ Capability → In-App Purchase.** RevenueCat's docs call for this. If your Xcode
     doesn't list it, that's fine — StoreKit needs no entitlement, and In-App Purchase is
     enabled by default on every explicit App ID, so there is nothing to toggle in the
     developer portal either.

   Xcode registers the App ID, issues a development certificate and creates the profile.
   To do it by hand instead: [developer.apple.com](https://developer.apple.com/account/resources/identifiers/list)
   → *Identifiers* → **+** → *App IDs* → *App* → explicit Bundle ID `com.tetrilaunch.app`.
   No other capabilities are needed — no push, no sign-in, no App Groups.

3. **Run on a device:** plug in an iPhone, pick it, ⌘R. First launch needs the cert
   trusted: *Settings → General → VPN & Device Management → Trust*.

   The Simulator works for gameplay but **not** for purchases against real StoreKit — use
   a device with a sandbox account, or an Xcode StoreKit configuration file.

## 3. RevenueCat

### Dashboard

1. Create a project → add an **App Store** app with bundle ID `com.tetrilaunch.app`.
2. **App Store Connect shared secret** and an **In-App Purchase Key** (App Store Connect
   → Users and Access → Integrations → In-App Purchase → generate the `.p8`) — upload
   both to RevenueCat.
3. Point **App Store Server Notifications V2** at the URL RevenueCat gives you.
4. Create your products in App Store Connect, then in RevenueCat attach them to an
   **offering** and an **entitlement** named **`pro`** (that string is
   `PRO_ENTITLEMENT` in `app/src/lib/purchases.ts` — change both together).
5. Build a **paywall** for the offering. The app calls `presentPaywall()`, so pricing,
   copy and layout are all remote-configured and need no app update.

### Keys

Public SDK keys go in `app/.env` (gitignored):

```
VITE_REVENUECAT_IOS_KEY=appl_…
VITE_REVENUECAT_ANDROID_KEY=goog_…
```

These are publishable by design — they're safe in the client bundle. Without them the app
still builds and runs, and the store UI simply hides itself.

**Set them before any build you intend to ship.** Vite inlines `import.meta.env` at build
time; `npm run ios:sync` runs `scripts/verify-store-bundle.mjs` afterwards to assert the
RevenueCat SDK actually survived into `dist/`, because a dead-code-eliminated store is
otherwise invisible until someone taps Unlock and nothing happens.

### What's wired up

`app/src/lib/purchases.ts` is the whole integration:

| Function | Used by |
|---|---|
| `initPurchases()` | boot (`main.ts` constructor), fire-and-forget |
| `isPro()` / `onProChange()` | menu PRO badge, store button visibility |
| `presentPaywall()` | "★ Unlock Pro" — menu and Settings |
| `restorePurchases()` | "Restore Purchases" — Settings |
| `presentCustomerCenter()` | "Manage Subscription" — Settings, when entitled |

Off-native every one of them is a no-op and `purchasesReady()` stays false, so the web
build renders exactly as before.

**The `pro` entitlement currently unlocks a badge and nothing else** — what you actually
sell is still an open product decision. Candidates that don't disturb balance: cosmetic
cube/neon skins (non-consumable), a Pro subscription (daily seed, wider draft pool),
consumable continues.

### Sandbox testing

App Store Connect → Users and Access → **Sandbox** → Test Accounts. Sign in to the
sandbox account on the device under *Settings → Developer → Sandbox Apple Account*, not
in the main App Store account. Purchases are free and renewals are accelerated
(1 month ≈ 5 minutes).

## 4. App Store Connect

1. **Business** → accept the *Paid Applications* agreement, and complete banking + tax.
   **Until this is done StoreKit returns zero products** in sandbox and production alike —
   it's the most common cause of "no products found".
2. **Apps → + → New App** — platform iOS, unique name, Bundle ID `com.tetrilaunch.app`,
   SKU e.g. `tetrilaunch-ios`.
3. Create the in-app purchases, matching the product IDs configured in RevenueCat.
4. Bump versions before each upload, in the target's *General* tab:
   - *Version* (`MARKETING_VERSION`) — user-visible `1.0.0`.
   - *Build* (`CURRENT_PROJECT_VERSION`) — must strictly increase on **every** upload.
5. **Archive & upload:** destination **Any iOS Device (arm64)** → *Product → Archive* →
   Organizer → **Distribute App → App Store Connect → Upload**.
6. TestFlight processes the build; internal testers get it immediately.

### Listing requirements

- **Screenshots** — one iPhone set (6.9″) and one iPad set (13″), since the target is
  universal. Landscape, because the app is landscape-only.
- Description, keywords, support URL, **privacy policy URL**.
- Age rating questionnaire.
- Because the app sells something, review will also want a working purchase path — make
  sure the products are "Ready to Submit" and attached to the version.
- Export compliance is pre-answered via `ITSAppUsesNonExemptEncryption = false` in
  `Info.plist`.

### App Privacy answers

Two things leave the device: a leaderboard submission (the player's chosen display name
plus score/level/lines) and purchase traffic to Apple/RevenueCat.

- **User Content → Other User Content** — App Functionality, not linked to identity, not
  used for tracking.
- **Purchases** — App Functionality. RevenueCat's anonymous app-user ID is not an
  advertising identifier and the app does no tracking, so nothing goes under Tracking.

Still worth fixing before submitting: `app/index.html` pulls fonts from
`fonts.googleapis.com` at runtime, which sends the device IP to Google and degrades
offline. Self-hosting them in `app/public/fonts/` removes both problems.

## 5. Icons and launch screen

```
app/resources/icon.svg            1024² source (wordmark removed — unreadable at 40px)
app/resources/splash.svg          2732² launch screen source
app/scripts/rasterize-assets.mjs  svg → png
```

```bash
cd app && npm run assets:generate   # rasterises, then fills ios/App/App/Assets.xcassets
```

Edit the SVGs and re-run. iOS icons must be opaque and get their corners rounded by the
system, so the source is flattened onto `#07070f` and keeps its content inside the middle
~80%.

## 6. Everyday workflow

```bash
cd app
npm run ios:sync     # after web changes
npm run ios:open     # Xcode
npm run ios:run      # straight to a device / simulator
```

Re-run `ios:sync` whenever you add or update a Capacitor plugin — that's what rewrites
`Package.swift`.

## 7. Notes

- **Android** isn't generated in the repo (`npx cap add android` when you want it). One
  RevenueCat-specific step applies there: the main Activity's `launchMode` must be
  `standard` or `singleTop`, or backgrounding for payment verification cancels purchases.
- **Native-only config** lives in `app/capacitor.config.ts` (web-view behaviour) and
  `app/ios/App/App/Info.plist` (orientation, hidden status bar, `UIRequiresFullScreen`,
  export compliance). Both are committed.
- **No Mac?** Xcode Cloud, a GitHub Actions `macos-latest` runner, or Ionic Appflow can
  archive and upload; all need signing secrets. An App Store Connect API key plus
  `xcodebuild -allowProvisioningUpdates` is the least painful. Not set up in this repo.
